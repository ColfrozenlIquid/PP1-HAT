\section{Comparing Code Performance in Rust vs C++}

In systems programming, performance is a key metric for evaluating software efficiency, making the choice of programming language especially important. Rust promises zero-cost abstractions and performance comparable to C++, while also offering memory safety and fearless concurrency. To examine these claims, we developed separate tests for individual language features and measured their execution times.

We implemented dedicated tests using Google’s Benchmark \cite[]{GoogleBenchmark2025} library for C++ and Criterion.rs \cite[]{heislerBheislerCriterionrs2025} for Rust. Specifically, we designed distinct tests for various features, including sorting (using each language’s standard sort function), closures (using Rust’s closures and the equivalent C++ lambda functions), memory allocation and management, and iterator operations. Each test was executed individually in comparable environments to evaluate the performance of each feature. We show our findings in Table~\ref{tab:comp_1}. The code used for this analysis is available at \cite[]{sColfrozenlIquidBenchmark2025}.

\begin{table}[H]
    \centering
    \begin{tabular}{|c|c|c|c|c|}
        \hline
        & \multicolumn{2}{|c|}{Average Runtime (ns)} \\  
        \hline
        Test & Rust & C++ \\
        \hline
        Sorting & 238.56 & 241 \\
        Closure/ Lambda & 26.39 & 29.2 \\
        Memory & 26.85 & 27.2 \\
        Iterators & 26.31 & 29.2\\
        \hline
    \end{tabular}
    \caption{Comparison of Execution speed of similar Rust and C++ feature implementations}
    \label{tab:comp_1}
\end{table}

The results in Table~\ref{tab:comp_1} indicate that Rust and C++ deliver nearly identical execution times for each test, demonstrating that both Rust’s zero-cost abstractions and C++’s zero-overhead design compile to highly optimized code.

Furthermore, we evaluated more realistic workloads to compare C++ and Rust. Using GPT-4o, we generated JSON parsing code for both languages to process HTTP requests and JSON files. Our findings are presented in Table~\ref{tab:comp_2}.

\begin{table}[H]
    \centering
    \begin{tabular}{|c|c|c|c|c|}
        \hline
        & \multicolumn{2}{|c|}{Average Parsing Runtime (ns)} & \multicolumn{2}{|c|}{Lines of Code (LOC)} \\  
        \hline
        HTTP Request & Rust & C++ & Rust & C++ \\
        \hline
        unoptimized & 454.44 & 1828 & 22 & 20 \\
        optimized & 375.79 & 231 & 47 & 48 \\
        \hline
    \end{tabular}
    \caption{Comparison of Execution speed and Lines of Code for Rust and C++ parsing implementations}
    \label{tab:comp_2}
\end{table}

As shown in Table~\ref{tab:comp_2}, Rust (454.44 ns) outperforms C++ (1828 ns) in the initial HTTP request parsing implementation by a factor of 4×. However, after generating a more optimized implementation that leverages lower-level optimizations, C++ (231 ns) outperforms Rust (375.79 ns) by a factor of 1.6×. However, when comparing the LOC, both implementations have similar counts, yet Rust's initial implementation, with fewer lines of code, is more performant than C++'s. C++ only gains an advantage after applying lower-level optimizations, which result in over twice the LOC in both implementations. This demonstrates that, in this example, Rust provides high-level abstractions that yield efficient performance, whereas C++ requires more intricate low-level implementations to achieve superior speed.


\paragraph{}

According to the study "Rewrite it in Rust: A Computational Physics Case Study"\cite{veytsmanRewriteItRust2024}, Veytsman et al.\ implemented a physics simulation in both Rust and C++ to compare their performance. The Rust implementation was adapted from the C++ version but leveraged Rust’s features such as modules, closures, and iterators. When comparing the runtime of the sequential implementations, the Rust version (4.098s) was 1.6× faster than its C++ counterpart (7.521s).

The study also included a parallelized implementation using Rust’s Rayon library \cite[]{RayonrsRayon2025}, which significantly improved performance. The parallel Rust implementation achieved a runtime of 146.939s, compared to 487.63s for C++, yielding a 5.6× speedup. However, this comparison may be somewhat unfair, as C++ offers multiple parallelization libraries that were not utilized in this study. Nevertheless, the results highlight the ease and safety of parallel programming in Rust \cite{veytsmanRewriteItRust2024}.

Another study by J. Rotter and M. C. Lewis \cite[]{rotterNBodyPerformanceKDTree2022} examined Rust’s performance in an N-body simulation benchmark, comparing it against C++ and C. Their results showed that Rust and C++ exhibited similar performance, with Rust outperforming C++ at higher particle counts as seen in Table~\ref{tab:performance_1}.

\end{table}

In addition to performance, the study also analyzed memory usage. The findings revealed that Rust consistently consumed less memory than C++ at all particle counts, closely matching the efficiency of C as seen in Table~\ref{tab:performance_2}.

These studies suggest that Rust is a strong competitor to C++ in high-performance computing. Rust consistently achieves performance comparable to C++, occasionally surpassing it, while also demonstrating efficient memory usage \cite[]{rotterNBodyPerformanceKDTree2022}.
