\chapter{Conclusion}
\label{chap:conclusion}

Rust has become a significant contender in the field of systems programming. Its demand has steadily increased over the past few years, showing no signs of decline. According to Stack Overflow, Rust has consistently been one of the most admired programming languages\cite[]{Technology2024Stack}, a title it has held since 2016, after being briefly surpassed by C++11 in 2015. With the growing emphasis on memory safety in systems programming, Rust is poised to challenge C++, the long-standing industry standard. As discussed in Chapter~\ref{chap:real_world} on real-world adoption, many major technology companies are incorporating Rust into their development stacks.

However, widespread adoption of Rust still faces challenges. As outlined in Chapter~\ref{chap:development}, one of the most common criticisms of Rust is its steep learning curve, particularly due to the constraints imposed by its borrow checker. Unlike traditional memory management approaches used in C and C++, Rust requires developers to rethink data ownership, which can be a significant hurdle. Nevertheless, Rust remains more approachable than purely functional languages like Haskell, and many developers express willingness to adopt it—provided the job market and industry adoption continue to grow.

\paragraph{}

Performance comparisons between Rust and C++ generally show similar raw execution speeds, with Rust occasionally outperforming C++. Additionally, Rust often demonstrates superior memory efficiency, sometimes even surpassing C. However, performance ultimately depends on implementation details, making direct comparisons between Rust and C++ inherently complex. Future research should focus on case studies examining system rewrites from C++ to Rust to better understand the practical implications of this transition.

\paragraph{}

Evaluating Rust and C++ solely based on safety is also challenging. While statistics indicate that Rust significantly reduces memory safety vulnerabilities compared to C++, both languages can be used safely or unsafely depending on the developer’s practices. However, regardless of individual developer fallibility, Rust is fundamentally designed around memory safety, embedding it as a core principle of the language. As software projects grow in complexity, reasoning about memory safety becomes increasingly difficult. Many developers, therefore, rely on Rust’s borrow checker and built-in safety guarantees, making it an increasingly compelling choice for the future of secure software development.
